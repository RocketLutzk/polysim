# Polysim — перевірка стратегій на Polymarket без реальних грошей

Бот бере **публічні** ціни Polymarket, сам обирає ставки за стратегією,
записує їх у базу, а коли ринок закривається, рахує, скільки б ми
заробили чи втратили. Гаманця, ключів і реальних ордерів немає взагалі.

## Запуск на GitHub (безкоштовно, без сервера)

GitHub сам запускає бота приблизно кожні 15 хвилин, зберігає дані в цей
репозиторій і публікує сторінку зі звітом. Комп'ютер можна вимкнути.
Усе робиться в браузері на комп'ютері, хвилин за 10.

### 1. Створи репозиторій
1. Зареєструйся на [github.com](https://github.com) (або увійди).
2. Праворуч угорі **+ → New repository**.
3. **Repository name:** `polysim`. Обери **Public** (для приватного безкоштовних хвилин не вистачить).
   Галочки «Add a README» **не** став. Натисни **Create repository**.

### 2. Завантаж файли
1. Розпакуй `polysim.zip` і відкрий папку `polysim`.
2. На сторінці нового репозиторію натисни посилання **uploading an existing file**.
3. Виділи **увесь вміст** папки `polysim` (папки `.github`, `polysim`, `tests`, `deploy`
   і файли) та перетягни у вікно браузера. Унизу натисни **Commit changes**.
4. Перевір, що в репозиторії є папка `.github`. Якщо її немає (на Mac вона прихована):
   **Add file → Create new file**, у назві введи `.github/workflows/collect.yml`,
   встав вміст однойменного файлу з архіву і натисни **Commit changes**.

### 3. Дозволь боту зберігати дані
**Settings → Actions → General →** унизу **Workflow permissions →
Read and write permissions → Save**.

### 4. Перший запуск вручну
1. Вкладка **Actions**. Якщо GitHub попросить, натисни зелену кнопку, що вмикає workflows.
2. Ліворуч обери **Збір даних Polymarket → Run workflow → Run workflow**.
3. Через ~1 хв з'явиться зелена галочка ✓, а в репозиторії — папки `data` і `docs`.

Відкрий запуск → крок «Один цикл». Якщо бачиш `✓ ринків: 2800, нових ставок: …` —
усе працює. Якщо там помилка з'єднання з Polymarket — з серверів GitHub дані
недоступні, тоді переходь до варіанту з власним сервером (нижче).

### 5. Увімкни сторінку зі звітом
**Settings → Pages → Build and deployment → Source: Deploy from a branch →
Branch: `main`, папка `/docs` → Save.**
За 1–2 хв веб-додаток буде за адресою `https://ТВІЙ_ЛОГІН.github.io/polysim/` —
відкривай її з телефону. Сторінка публічна, але гроші й дані там не секретні.

### Що є в додатку
- **Огляд** — загальний P&L (закриті + відкриті за поточною ціною), графік прибутку
  по стратегіях у часі, таблиця стратегій з висновком «є перевага / випадковість / програє».
- **Ставки** — усі ставки з пошуком і сортуванням. Натисни на ставку: деталі,
  причина, графік ціни з моменту ставки і лінія ціни входу.
- **Аналіз** — групування за ціною входу, днями до закриття або стратегією.
  Графік «очікувалось vs вийшло» показує, де ринок помиляється, а ROI — де на цьому заробляли б.
- **Бот** — коли був останній запуск, скільки даних зібрано, помилки, посилання на дані.

Фільтри зверху (стратегії й період) діють на всі вкладки.

### Далі
- Бот запускається сам. Розклад GitHub неточний: інтервали бувають 15–40 хв,
  деякі запуски пропадають — це нормально.
- **Зупинити:** Actions → Збір даних Polymarket → «⋯» → **Disable workflow**.
- **Передати дані на аналіз:** на головній сторінці репозиторію **Code → Download ZIP**
  і надішли архів. Або сам збери все в одну базу:
  `python -m polysim gh-import` → `polysim_all.sqlite`.
- Якщо 60 днів у репозиторії не буде змін, GitHub вимкне розклад — увімкни на вкладці Actions.

Де що лежить:
```
data/bets.csv          віртуальні ставки
data/markets.csv       ринки, які бачив бот
data/runs.csv          журнал запусків (і помилок)
data/snapshots/ДАТА/   знімки цін, по файлу на запуск
docs/                  веб-додаток (index.html, app-data.json, series.json)
```

## Встановлення на свій комп'ютер

Потрібен Python 3.10+.

```
pip install -r requirements.txt
```

## Два режими

### 1. Бектест — відповідь одразу
Бере вже закриті ринки з минулого. Для кожного «перемотує час» на 7, 3 і 1 день
до закриття, дивиться тодішню ціну, приймає рішення і одразу знає результат.

```
python -m polysim backtest --from 2026-06-01 --to 2026-09-30
```

Корисні опції:
- `--days-before 3` — бот дивиться на ринок лише за 3 дні до кінця
- `--max-markets 2000` — скільки ринків перевірити (більше = довше, але точніше)
- `--min-volume 50000` — лише ринки з обсягом від $50k
- `--strategies favorite,random` — лише вибрані стратегії
- `--stake 10` — розмір віртуальної ставки
- `--slippage 0.01` — штраф 1 цент до ціни входу (реальний спред)
- `--fee 0.01` — комісія 1% від ставки

### 2. Паперова торгівля — наживо
Бот дивиться на ринки зараз, записує ставки, а через дні/тижні розраховує їх.

```
python -m polysim run --every 60      # перевірка щогодини, Ctrl+C — стоп
```
або вручну: `python -m polysim scan`, згодом `python -m polysim settle`.

## Запуск на власному сервері (якщо GitHub не підійшов)

Боту вистачає найменшого сервера: 1 CPU, 1 ГБ RAM, Ubuntu 22.04/24.04 або Debian 12.
Даних набирається ~20–30 МБ на добу.

**1. Орендуй сервер** у Німеччині, ОС — Ubuntu 24.04. Запиши IP і пароль root.

**2. Завантаж код на сервер.** На своєму комп'ютері (Windows: PowerShell) в папці з архівом:
```
scp polysim.zip root@IP_СЕРВЕРА:
```

**3. Підключись і встанови:**
```
ssh root@IP_СЕРВЕРА
apt-get install -y unzip && unzip -o polysim.zip && cd polysim
bash deploy/setup.sh
```
Скрипт сам перевірить, чи відкриваються дані Polymarket з цього сервера.
Якщо ні — зупиниться і нічого не запустить.

**4. Відкрий звіт з телефону:** скрипт у кінці покаже адресу
`http://IP:8080/`, логін `admin` і пароль. Збережи пароль.

Що працює на сервері:
- кожні 15 хв бот робить «знімок» цін усіх активних ринків (ціна, bid/ask, обсяг);
- стратегії записують віртуальні ставки;
- ставки на закритих ринках розраховуються автоматично;
- після перезавантаження сервера все стартує саме.

Сторінка — той самий веб-додаток, що й на GitHub. На вкладці «Бот» є кнопки завантаження ставок (CSV) і всієї бази —
надішли базу мені, і ми розберемо результати або перевіримо нові стратегії на зібраних даних.

Корисні команди на сервері:
```
journalctl -u polysim-bot -f        # що бот робить зараз
systemctl stop polysim-bot          # зупинити збір
systemctl start polysim-bot         # запустити знову
sudo cat /etc/polysim.env           # нагадати пароль
```
Оновити код: завантаж новий `polysim.zip`, розпакуй і знову `bash deploy/setup.sh`
(зібрані дані й пароль залишаться).

Сторінка працює по http, без шифрування. Для віртуальних даних це нормально,
але не використовуй цей пароль більше ніде.

## Результати

```
python -m polysim report
```
Таблиця в консолі + `report.html` з графіком накопиченого прибутку.

Як читати:
- **Виграш %** — як часто ставка заходила.
- **Ринок очікував %** — як часто вона *мала б* заходити за цінами входу.
- Перевага є лише тоді, коли «Виграш» **стабільно** вищий за «Ринок очікував»
  на 30+ ставках. Колонка «Висновок» підказує це автоматично.
- Стратегія `random` — монетка. Якщо твоя стратегія не обганяє її, вона нічого не варта.

## Стратегії (`polysim/strategies.py`)

| Назва | Логіка |
|---|---|
| favorite | фаворит із ціною 80–95% за 1–7 днів до кінця |
| longshot | аутсайдер 3–15% (зазвичай програє — це нормально) |
| momentum | ціна різко рухнула/зросла за добу → ставимо в той бік |
| random | випадкова сторона, еталон |

Свою стратегію додати просто: скопіюй клас, зміни `name` і умови в `decide()`,
додай у список `ALL` внизу файлу.

## Важливо

- **Доступ до даних.** Бот читає `gamma-api.polymarket.com` і
  `clob.polymarket.com`. В Україні домен Polymarket заблоковано з грудня 2025 р.,
  тому з твоєї мережі ці адреси можуть не відкриватися — тоді бот покаже помилку.
- **Бектест оптимістичний.** Він не знає реальної глибини стакану, тому
  великі ставки в житті коштували б дорожче. Закладай `--slippage`.
- **Гарний бектест ≠ прибуток.** Якщо підкручувати параметри, поки графік не стане
  гарним, бот «вивчить» минуле, а не знайде перевагу. Перевіряй на іншому періоді.

## Тести

```
python -m unittest discover tests
```
Тести працюють без інтернету на синтетичному «чесному» ринку і перевіряють,
що жодна стратегія там не знаходить фальшивої переваги.
